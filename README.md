# Checkers

Russian checkers against the computer on three difficulty levels. Flutter,
a single package, feature-first Clean Architecture, bloc.

## Features

- Complete rules of Russian checkers: flying kings, mandatory capture with a
  free choice of sequence, mandatory continuation of a capture, the
  "Turkish strike", promotion to king in the middle of a capture.
- Draws: 15 king-only moves per side without a capture, threefold
  repetition, three kings failing to beat a lone king within 15 moves.
- Computer: negamax with alpha-beta, a transposition table (Zobrist),
  iterative deepening under a time budget; the search runs in `Isolate.run`.
- Side choice, undo, moves animated along their whole path, the computer's
  move shown in notation (`c3-d4`, `c3:e5:g7`).
- Win / loss / draw statistics per level.
- Accessibility: every board square is a TalkBack / VoiceOver node with a
  name, state and action; turn status and results are announced (live
  regions); large text and disabled animations are respected.
- Russian and English UI (`flutter gen-l10n`, ARB, `plural` / `select`).

| Level | Search | Random moves |
|---|---|---|
| Easy | 1 half-move | 50 % |
| Medium | 4 half-moves | 10 % |
| Hard | up to 10 half-moves, at most 1.2 s | never |

Pending captures are always searched to the end, so even "Easy" does not
walk into an obvious exchange.

## Running

```bash
flutter pub get
flutter run                              # dev environment
flutter run --dart-define=ENV=prod       # prod environment; an unknown ENV fails at start
```

Checks:

```bash
flutter analyze
flutter test --exclude-tags golden       # unit, bloc, widget and architecture tests
flutter test --tags golden               # pixel snapshots of the board (references made on macOS)
```

A full game on a device or simulator (skipped on the host):

```bash
flutter drive --driver=test/integration/driver.dart \
  --target=test/integration/app_test.dart -d <device>
```

After changing DI or DTOs: `dart run build_runner build`.
Strings: `lib/core/l10n/arb/app_ru.arb` (template) and `app_en.arb`; the
code is generated by `flutter pub get`, `flutter run` or `flutter gen-l10n`.
Icon and splash (`tool/` is an asset generator, not a test — it only runs
through `flutter test` to draw on a Flutter `Canvas`):
`flutter test tool/render_icon.dart`, then `dart run flutter_launcher_icons`
and `dart run flutter_native_splash:create`.

## Structure

```
lib/
  main.dart                      the only entry point
  app/                           composition of the app: nothing imports it
    bootstrap.dart, app.dart     start-up, MaterialApp.router
    di/                          ALL DI registrations (modules/), environment
    router/                      routes of every feature + ScreenViewObserver
    observers/                   global error handlers, BlocObserver
  core/                          shared technical code, split by topic
    analytics/  monitoring/      Analytics and ErrorReporter ports, no-op implementations
    storage/                     KeyValueStorage + SharedPreferences
    exceptions/  usecases/       AppException, UseCase, NoParams
    l10n/  navigation/           strings (ARB), route paths and screen names
    theme/  widgets/             design tokens, theme, AppButton, AppPageLayout
                                 (shared page frame: Scaffold + AppBar + SafeArea)
  features/
    shared/game_results/         business concepts shared by features (shared kernel, not a feature):
                                 Difficulty, GameOutcome, GameResult, LevelStats,
                                 GameResultRecorder port
    menu/presentation            side and level choice
    game/domain, presentation    rules, AI, use cases, GameBloc, board
    statistics/domain, data, presentation
test/                            mirrors lib/ file by file + architecture_test.dart
  integration/                   a game on a device (flutter drive)
  reports/                       mutation testing reports (not in git)
tool/                            icon and splash generator
```

Inside a feature, `presentation/pages/` holds one file per screen with the
page widget only; every other widget is a public class in its own file in
`pages/widgets/`.

Features never import each other. The game hands finished games to the
`GameResultRecorder` port in `features/shared/`; the statistics feature
implements it and `app/di/modules/statistics_module.dart` binds the two.

### Import rules (checked by `test/architecture_test.dart`)

| Folder | May import |
|---|---|
| `core/analytics`, `exceptions`, `monitoring`, `usecases` | plain Dart and each other only |
| `core/storage` | platform plugins, pure core folders; no UI |
| `core/l10n`, `navigation`, `theme`, `widgets` | Flutter, pure core folders; not `storage` |
| `features/shared/` | plain Dart, `core/exceptions`, `core/usecases` |
| `features/<f>/domain` | plain Dart, `core/exceptions`, `core/usecases`, `features/shared/`, its own domain |
| `features/<f>/data` | the same + `core/storage`, its own data; no Flutter |
| `features/<f>/presentation` | all of core except `storage`; `features/shared/`, its own domain and presentation |

Also: `core` sees neither features nor `app`; features see each other only
through `features/shared`; `injectable` is used only in `app/di`; `GetIt`
only in `routes/` and `app/di`; every file with logic has a mirrored test.
A new folder in `core` that is not assigned to a group fails the test.

## Analytics and error monitoring

`Analytics` and `ErrorReporter` are ports in `core/`. Today they are bound to
`NoopAnalytics` and `NoopErrorReporter`, so everything goes nowhere. To plug
in a product, add an adapter next to the port and change one binding in
`app/di/modules/core_module.dart`:

```dart
@lazySingleton
Analytics analytics(FirebaseAnalytics firebase) =>
    FirebaseAnalyticsAdapter(firebase);
```

Events: `game_started {difficulty, color}`, `game_finished {difficulty,
outcome}`, `move_undone {difficulty}`, `stats_reset`, screen views `home` /
`game` / `statistics`. Errors: everything that reaches
`FlutterError.onError`, `PlatformDispatcher.onError` and
`Bloc.observer.onError`; the handlers are installed before DI, so a failure
during start-up is not lost.

## Testing

- Domain, data layer, blocs, pages, routes, DI — unit and widget tests.
- AI behaviour, not its constants: the deep search finds a sacrifice
  followed by a capture that a one-half-move search misses; "Medium" beats
  "Easy" in most games.
- Accessibility on every page: `meetsGuideline` (labels, tap target size,
  contrast) and layout at 200 % text; a move on the board can be made
  through semantics, the way a screen reader does it.
- Golden snapshots of the board, an integration test of a game on a device.
- Mutation testing (`dart pub global activate dart_mutant`):

```bash
dart_mutant run lib/features/shared/game_results/game_result.dart lib/features/shared/game_results/level_stats.dart \
  lib/core/analytics/analytics_event.dart lib/core/analytics/track_event.dart \
  'lib/features/*/domain/usecases/**.dart' 'lib/features/*/domain/value_objects/**.dart' \
  'lib/features/*/domain/entities/**.dart' 'lib/features/*/domain/services/**.dart' \
  'lib/features/*/data/mappers/**.dart' 'lib/features/*/data/repositories/**.dart' \
  'lib/features/*/data/datasources/**.dart' 'lib/features/*/presentation/bloc/**/*_bloc.dart' \
  --report test/reports/mutation/mutation.json --html test/reports/mutation/index.html
```
